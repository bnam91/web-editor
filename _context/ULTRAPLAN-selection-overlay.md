# 울트라플랜 — 선택 표시를 «오버레이 층»으로

발주: 현빈 2026-09-06.
> 「텍스트블럭끼리 위아래 있는경우, 아웃라인이 더 진해져보이는것도 그렇고
>   이런것들이 완성도를 떨어트리는 부분들같아. 피그마의 오토레이아웃도 우리처럼 그런거야?」
> 「b로 진행해줘 울트라플랜으로 pge 적대적qa까지」

## 0. 한 문장
선택 테두리를 «문서(블록 CSS outline)»에 그리는 것을 그만두고, 핸들이 이미 쓰고 있는
**오버레이 층(`#ss-handles-overlay`)** 에서 그린다.

## 1. 왜 — 세 증상이 «한 뿌리»다 (전부 2026-09-06 실측)

| 증상 | 현빈 원문 | 실측 |
|---|---|---|
| ⑴ **가려짐** | 「밑에 로고에셋이 카드블럭의 아랫아웃라인을 덮어버려 가려버린다」 | 카드 bottom 349.1 = 로고 top 349.1(간격 0). 카드 outline-offset **+2.5px** 라 아웃라인이 349~354 를 차지하는데 둘 다 `z-index:auto` → DOM 뒤인 로고가 위에 그려짐. **픽셀 실측: 파랑우세 42 (위쪽 기준선 97)** |
| ⑵ **얹힘** | 「미세하게 카드블럭과 로고블럭이 겹쳐보여서」 | 블록 간 겹침은 **0**. 바깥 아웃라인이 이웃 위 5px 를 덮는 것. **바깥에 그리는 한 회피 불가** |
| ⑶ **두꺼워짐** | 「텍스트블럭끼리 위아래 있는경우 아웃라인이 더 진해져보이는」 | 안쪽 아웃라인이라 A의 아래선 `[A.bottom-1,A.bottom]` + B의 위선 `[B.top,B.top+1]` 이 **붙어서 2px 띠**. 착시가 아니라 **실제 2배** |

★셋 다 «선택 표시가 문서 레이아웃과 같은 좌표계·같은 페인트 순서에 있기 때문»이다.
  ⑴은 z-index 로 때웠고(2b6cfac 이후 커밋), ⑵·⑶은 그 방식으로는 못 고친다.
  ⑵를 고치려 안쪽으로 돌리면 카드는 배경이 가장자리까지 차서 «제 배경에 묻힌다».
  ⑶을 고치려 한쪽 선을 지우면 «어느 쪽을 지울지»가 선택 조합마다 달라진다.

★대조: 피그마도 오토레이아웃 요소는 우리처럼 «맞닿는다». 다른 것은 **선택 표시를 그리는 층**이다.
  (이 문장은 «메커니즘 설명»이지 실측이 아니다 — 플래너는 근거가 필요하면 확인할 것.)

## 2. 이미 있는 자산 (새로 만드는 게 아니다)
- `#ss-handles-overlay` — 리사이즈/반경/회전 핸들이 **이미 여기 그려진다**(js/overlay-handles.js).
- `_cornerScreen(el, dir, inset)` — **회전까지 반영한** 스크린 좌표 헬퍼가 이미 있다.
- rAF 추종 루프 4종(`_start*Raf`) — 스크롤·줌·드래그 중 위치 추종이 이미 돈다.
- `--sel-outline-w = calc(1px * var(--inv-zoom,1))` — 줌 불변 굵기 토큰.
⇒ **핸들은 이 층에 있어서 세 증상이 없다.** 테두리만 문서에 남아 계속 터진다.

## 3. 대상 인벤토리 (실측 · `_context/FACTS-selection-overlay.md`)
- `.블록.selected` 아웃라인 **28종** — 안쪽 24 / 바깥 4(canvas·banner02·icon-circle·overlay-tb)
- 부모가 대신 그리는 판: `.row:has(.text-block.selected)`, `.frame-block[data-text-frame]:has(...)`
  + 「T6 2겹 픽스」(자식 outline 을 transparent 로 되돌림) — **이 우회가 존재한다는 것 자체가 증상**
- `z-index: 2` 목록 **17종** — 목록 누락이 ⑴의 직접 원인. 이 파일에서만 세 번째 누락 사고
- 줌 보정 없는 하드코딩 아웃라인 **캔버스 안쪽 15곳**
  ⚠️처음에 42곳으로 셌다 — 패널·모달까지 세서 틀렸다. 패널은 스케일러 «밖»이라 줌 무관.
- ⛔**남은 결함 1건**: `overlay-tb.selected` = 바깥(offset 0) + z-index 없음 + `1.5px` 생짜

## 4. 성공 판정 (전부 «픽셀»로 닫는다 — 코드 대조 금지)
P0 인수조건. 각 항목은 **RED(현행)에서 빨강이 나오는 것을 먼저 보인 뒤** GREEN 을 재는 양성대조 필수.
1. **가려짐 0** — 맞닿은 임의 블록쌍에서 선택 테두리의 파랑우세가 «가릴 이웃이 없는 변»과 **동일**
2. **두께 균일** — 맞닿은 두 블록을 «둘 다» 선택해도 경계 두께가 단일 변과 같다(2px 띠 0)
3. **이웃 불가침** — 선택해도 이웃 블록의 픽셀이 **한 점도** 안 바뀐다(선택 전후 diff)
4. **줌 불변** — 10 / 40 / 100 / 400% 에서 화면상 굵기가 같다(±1 디바이스픽셀)
5. **회전 추종** — 회전한 블록·프레임 안쪽 자유배치 블록에서 테두리가 상자와 일치
6. **내보내기 무유출** — export HTML/PNG 에 선택 표시가 **0 픽셀**(양성대조로 검출력 증명)
7. **회귀 0** — 단위 669 유지 + 핸들 동작(4모서리·반경·회전) 무회귀

## 5. 명시적 «비범위»
- 호버 표시·드래그 인디케이터·드롭 가이드 — 이번엔 안 옮긴다(범위 폭발 방지)
- 패널/모달 CSS 의 아웃라인 15곳 밖 — 스케일러 밖이라 이 문제와 무관
- 성능 최적화 — 추종 루프가 이미 돌고 있으므로 «현행 유지»가 기준선

## 6. ⛔알려진 함정 (오늘 실측으로 데인 것들)
- `elementFromPoint` 는 **아웃라인을 못 본다**(히트테스트 대상 아님) → 판정에 쓰지 말 것
- 스크린샷 배율을 **가정하지 마라** — `shot.height / window.innerHeight` 로 «재라»(1440 가정해서 틀렸다)
- `getComputedStyle` 은 **살아있는 객체** — 상태를 되돌린 «뒤»에 읽으면 되돌린 값이 나온다
- 40% 축소에서 아웃라인은 안티에일리어싱으로 흐려진다 → 정확일치 임계는 오탐. **파랑우세(b−r)** 로 재라
- 「목록으로 관리되는 규칙」은 새 블록이 생기면 조용히 빠진다 → **목록 자체를 검사로 고정**할 것
- 세는 식은 «그 대상을 실제로 볼 수 있는지»부터 증명해라(오늘 이 팀에서만 6회 발생)
